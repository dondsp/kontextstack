# Runtime rollback

Before provider actions record previous artifact/revision, exact private root,
startup file, runtime version, environment-name contract, dependency install
requirements, restart method and verified baseline. Keep values in approved stores.

On startup, route, dependency or proxy failure stop changes and retain sanitized
current evidence. Obtain explicit recovery approval. Restore the reviewed prior
artifact at the same scoped private root, reconcile dependencies and restore
approved prior host settings, then restart only that application.

Repeat liveness/readiness, assets, direct routes, APIs, errors, logs and browser
journey. File/runtime rollback does not undo a migration or change identity state;
those have separate owners and recovery decisions. Keep both artifact identities
and mark recovery accepted only after the owner reviews observed results.
